# Перенос музыки

Локальный прототип переноса. Цель — лайки и плейлисты в любом направлении между Spotify, Apple Music, Яндекс.Музыкой и Сбер.Звуком. Экспериментальные локальные readers есть для всех четырёх сервисов. Все четыре сервиса получили fixture-tested target writers. Ни один writer пока не прошёл live-проверку записи в аккаунт; Spotify зависит от частных API Web Player.

## Быстрый старт

Бесплатный пробный запуск: скачайте `music-importer-chrome-extension` из **Artifacts** последнего успешного workflow **Verify Music Importer** в GitHub Actions и распакуйте архив полностью. На macOS запустите `INSTALL-MACOS.command`: он откроет страницу расширений Chrome и нужную папку. Включите режим разработчика, нажмите «Загрузить распакованное» и выберите `chrome-extension`. На других ОС выберите эту папку вручную. Артефакт собирается после успешных проверок и хранится 30 дней. Для Edge также собирается `music-importer-edge-addons.zip` с корневым manifest; магазин Edge не требует регистрационного сбора, но перед публикацией нужны проверка совместимости, listing и review. Публикация в Chrome Web Store не настроена; Google требует одноразовую регистрацию developer account и отдельное прохождение review. Подробнее о вариантах распространения: [docs/DISTRIBUTION.md](docs/DISTRIBUTION.md).

Если вы работаете с исходниками, соберите bundle локально:

```bash
node scripts/build-extension-app.mjs
```

Один раз загрузите папку `chrome-extension/` из checkout либо извлечённую папку с `manifest.json` через `chrome://extensions` → **Режим разработчика** → **Загрузить распакованное расширение**. При первой установке расширение само откроет полный интерфейс и начнёт сканирование; отсутствующие страницы сервисов откроются в фоне. При последующих запусках один клик по значку Music Importer откроет этот же основной интерфейс независимо от активной вкладки. Если для сервиса ещё нет входа, нажмите «Войти» в карточке.

Интерфейс живёт внутри расширения: ему не нужен отдельный локальный сервер или разрешение на `localhost`. Пароли и cookies не запрашиваются. После изменения кода пересоберите bundle этой командой и один раз нажмите **Обновить** у Music Importer на `chrome://extensions`; версия расширения отображается в карточке. Если вкладка сервиса ещё держит старый content script, приложение перехватит сбой связи и при следующем сканировании автоматически перезагрузит эту вкладку. Старое сообщение `Extension context invalidated` может остаться в журнале ошибок Chrome от прежнего bridge; установленной после обновления версии оно не соответствует. Установка остаётся распакованной; публикации в Chrome Web Store пока нет.

Локальная веб-страница остаётся запасным вариантом:

```bash
./scripts/run-local.sh
```

Для неё требуется отдельное разрешение Chrome на локальный origin. Основной сценарий через страницу внутри расширения этого разрешения не требует. Текущая версия manifest: `0.13.43`.

Интерфейс по умолчанию следует системной светлой или тёмной теме. Переключатель в верхней панели позволяет выбрать системную, светлую или тёмную тему; выбор хранится локально в браузере.

При обновлении библиотек приложение оставляет предыдущий подтверждённый снимок доступным, пока новый сбор не завершится. Если сервис недоступен или сканирование оборвалось, старый снимок явно помечается как не обновлённый, а неполные данные не считаются готовой библиотекой.

При первом запуске сканирование само открывает недостающие страницы сервисов в фоне и проверяет активные сессии; переключаться между ними не нужно. Если сервис просит войти, кнопка «Войти» переводит на его вкладку; после возвращения библиотека сканируется автоматически. Вкладки нужны текущему расширению для доступа к сессиям страниц сервисов, и их можно оставить в фоне. Сбор Сбер.Звука последовательно читает избранное и страницы плейлистов в его вкладке. Приложение показывает полные библиотеки и позволяет выбрать источник и цель; поиск совпадений запускается автоматически после выбора цели. Неоднозначные совпадения остаются в очереди проверки.

Можно загрузить CSV/JSON или просканировать аккаунты четырёх сервисов. После подключения расширения недостающие страницы сервисов открываются в фоне, сканирование запускается автоматически; повторное доступно кнопкой. Пользователь входит обычным способом на сайтах сервисов; приложение не требует создавать OAuth-приложение автора и не принимает пароль. После сканирования выберите источник и целевой сервис — массовый поиск совпадений начнётся автоматически. Текущая версия требует установленного extension; страницы сервисов остаются фоновыми вкладками, так как reader и writer выполняют запросы в сессионном контексте сайта. Сбор Сбер.Звука читает favorites и страницы плейлистов в его вкладке. Неоднозначные совпадения остаются в review. Подробный статус каждой направленной пары указан в [матрице возможностей](docs/TRANSFER_CAPABILITY_MATRIX.md).

Для Apple Music и Spotify при наличии исходного ISRC выполняется точный каталоговый поиск по этому коду с fallback на название и исполнителя; для остальных сервисов ISRC учитывается, когда его возвращает поисковый каталог. Экран сверки отображает не более 50 записей за раз и фильтрует только требующие внимания.

Поддерживаемый CSV: обязательные `title,artist`, дополнительные `album,isrc,duration_ms,id` (также понимаются `Track Name,Artist Name(s)` и русские `название,исполнитель`; разделители запятая, точка с запятой или табуляция). JSON — массив объектов с `title`/`artist` либо `tracks`, `items` или `data` с таким массивом. Для объектов с вложенным `track` поля также распознаются. Общая provider-neutral модель snapshot/plan находится в [`demo/transfer-core.js`](demo/transfer-core.js), общий контракт поиска и постраничного чтения — в [`demo/transfer-engine.js`](demo/transfer-engine.js), контракт account adapters — в [`docs/ADAPTER_CONTRACT.md`](docs/ADAPTER_CONTRACT.md). Yandex writer использует вкладку с активной сессией, не читает и не сохраняет токены, требует подтверждённый полный snapshot и явное согласие перед записью.

Это ещё не готовый универсальный перенос. Все target writers проверены на fixtures, но ни один не проверен записью в живой аккаунт; Spotify использует частные Web Player API. Все 12 комбинаций перечислены в [матрице возможностей](docs/TRANSFER_CAPABILITY_MATRIX.md), включая обязательные live-проверки. Полный охват и критерии готовности описаны в [PRODUCT_REQUIREMENTS.md](docs/PRODUCT_REQUIREMENTS.md).
