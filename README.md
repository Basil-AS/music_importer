# Перенос музыки

Локальный прототип переноса. Цель — лайки и плейлисты в любом направлении между Spotify, Apple Music, Яндекс Музыкой и Звуком. Экспериментальные локальные readers есть для всех четырёх сервисов. Все четыре сервиса получили fixture-tested target writers. Ни один writer пока не прошёл live-проверку записи в аккаунт; Spotify зависит от частных API Web Player.

## Быстрый старт

```bash
./scripts/run-local.sh
```

Откройте адрес, напечатанный скриптом. Скрипт всегда раздаёт `demo/` из того же checkout, где он находится, и печатает точную папку расширения для этого checkout. Если порт 8001 занят, используйте поддерживаемый запасной порт: `MUSIC_IMPORTER_PORT=8000 ./scripts/run-local.sh`. Сервер нужен для поиска каталога и связи с расширением; при открытии HTML напрямую браузер может заблокировать сетевые запросы.

Для чтения библиотек и записи через аккаунтную сессию загрузите именно папку `chrome-extension/` из текущего checkout через `chrome://extensions` → **Режим разработчика** → **Загрузить распакованное расширение**. В настройках расширения разрешите доступ к адресу, напечатанному скриптом, и вкладкам сервисов; если Chrome оставляет доступ «по нажатию», bridge не ответит. После обновления кода нажмите **Обновить** у расширения и перезагрузите вкладки сервиса и приложения. Страница показывает результат handshake. Поддерживаются localhost на портах 8000/8001 и проектный адрес GitHub Pages. Подробности публикации см. [GitHub Pages](docs/GITHUB_PAGES.md); Pages пока не включён в настройках репозитория.

Popup расширения показывает открытые вкладки четырёх сервисов и отдельно проверяет, отвечает ли страница Music Importer. Наличие вкладки не доказывает, что пользователь вошёл в аккаунт: авторизация проверяется при чтении библиотеки.

Текущая версия manifest: `0.11.0`.

При обновлении библиотек приложение оставляет предыдущий подтверждённый снимок доступным, пока новый сбор не завершится. Если сервис недоступен или сканирование оборвалось, старый снимок явно помечается как не обновлённый, а неполные данные не считаются готовой библиотекой.

Запускайте сервер из checkout ветки `feature/interactive-importer-mvp`. Если параллельно переключаете основную папку проекта на ветку исследования, держите MVP в отдельном Git worktree: при переключении ветки каталог `demo/` исчезает из checkout, и оставшийся сервер начинает отвечать `404`.

Можно загрузить CSV/JSON или просканировать открытые авторизованные вкладки четырёх сервисов. После подключения расширения сканирование запускается автоматически; повторное доступно кнопкой. Пользователь входит обычным способом на сайтах сервисов; приложение не требует создавать OAuth-приложение автора и не принимает пароль. После сканирования выбираются источник и цель. Для работы нужен установленный extension и открытые авторизованные вкладки. Сбор Звука последовательно открывает favorites, каталог и страницы плейлистов в его вкладке. Неоднозначные совпадения остаются в review. Подробный статус каждой направленной пары указан в [матрице возможностей](docs/TRANSFER_CAPABILITY_MATRIX.md).

Для Apple Music и Spotify при наличии исходного ISRC выполняется точный каталоговый поиск по этому коду с fallback на название и исполнителя; для остальных сервисов ISRC учитывается, когда его возвращает поисковый каталог. Экран сверки отображает не более 50 записей за раз и фильтрует только требующие внимания.

Поддерживаемый CSV: обязательные `title,artist`, дополнительные `album,isrc,duration_ms,id` (также понимаются `Track Name,Artist Name(s)` и русские `название,исполнитель`; разделители запятая, точка с запятой или табуляция). JSON — массив объектов с `title`/`artist` либо `tracks`, `items` или `data` с таким массивом. Для объектов с вложенным `track` поля также распознаются. Общая provider-neutral модель snapshot/plan находится в [`demo/transfer-core.js`](demo/transfer-core.js), общий контракт поиска и постраничного чтения — в [`demo/transfer-engine.js`](demo/transfer-engine.js), контракт account adapters — в [`docs/ADAPTER_CONTRACT.md`](docs/ADAPTER_CONTRACT.md). Yandex writer использует вкладку с активной сессией, не читает и не сохраняет токены, требует подтверждённый полный snapshot и явное согласие перед записью.

Это ещё не готовый универсальный перенос. Все target writers проверены на fixtures, но ни один не проверен записью в живой аккаунт; Spotify использует частные Web Player API. Все 12 комбинаций перечислены в [матрице возможностей](docs/TRANSFER_CAPABILITY_MATRIX.md), включая обязательные live-проверки.
