# Интерактивный прототип сопоставления

Целевая функция проекта — двусторонний перенос коллекций между Spotify, Apple Music, Яндекс Музыкой и Звуком. Текущая ветка покрывает только файловый источник и Apple-каталожный поиск; её нельзя считать MVP всего продукта.

## Что можно попробовать

1. Выбрать сервис, откуда взят экспорт. Это подпись источника, вход в аккаунт пока не выполняется.
2. Загрузить демонстрационный список или свой CSV/JSON-файл с полями названия и исполнителя.
3. Искать композиции в каталоге Apple. Сопоставитель автоматически выбирает только единственный результат с высокой уверенностью; неоднозначные результаты остаются на ручную проверку.
4. При необходимости поправить запрос или версию, исключить запись либо выбрать совпадение вручную.
5. Скачать JSON-план `music-transfer-plan` с source/target provider IDs, исходными ID/ISRC/метаданными, target track IDs, методом и оценкой совпадения, playlist-порядком, полнотой и пропусками.

## Данные и границы

- CSV и JSON читаются браузером и не отправляются на сервер проекта.
- Поиск обращается напрямую из браузера к публичному Apple iTunes Search API. Apple получает введённые названия и исполнителей. Поддерживаются storefronts AE, US, GB, CA и AU.
- Первичный порог авто-подбора консервативный и пока не откалиброван на реальных библиотеках: exact ISRC принимается автоматически; по метаданным — только при уверенно высоком score и заметном отрыве от второго кандидата. Совпадение версий (live/remix/remaster и др.) проверяется отдельно. Массовый перенос тысяч записей ещё не подтверждён.
- Matcher, `demo/transfer-core.js` и `demo/transfer-engine.js` отделяют модель данных, план и orchestration от сервисов: общий поиск объединяет повторы и ограничивает конкуренцию, общий reader проходит cursor-страницы и сохраняет playlist positions. Модель допускает любой из четырёх сервисов как источник/назначение; реальный network adapter пока есть только для поиска по публичному Apple каталогу.
- План описывает нативное действие `add_to_favorites` или `add_to_playlist`, но ни одна запись в сервис назначения не выполняется. В файле `mode` равен `preview-only`, а `execution.writesPerformed` — `0`.
- Вход и импорт лайков из Spotify, Звука и Яндекс Музыки не подключены. Нужно сначала выгрузить свой список треков в CSV/JSON.

## Запуск

Из корня проекта:

```bash
python3 -m http.server 8000 --bind 127.0.0.1 --directory demo
```

Открыть <http://127.0.0.1:8000>. Для сетевого поиска нужен локальный HTTP-сервер: при открытии `index.html` как `file://` браузер может заблокировать запрос к каталогу.

Сервер раздаёт файлы из текущего checkout. Если переключить checkout на ветку, где нет `demo/`, уже запущенный сервер продолжит слушать порт, но будет возвращать `404`. Для параллельной работы с исследовательской веткой используйте отдельный worktree для `feature/interactive-importer-mvp` и запускайте команду из него.

## Ручная проверка

В браузере проверены поиск для 6 демо-треков, формирование и скачивание provider-neutral JSON-плана: `type=music-transfer-plan`, source `zvuk`, target `apple-music`, три операции и три записи review/skip, `execution.writesPerformed=0`. Дополнительно загружен JSON fixture в формате Zvuk playlist export: оба трека распознаны, порядок/тип коллекции показаны, ошибок консоли нет. Это проверяет импорт и preview schema на маленьких данных, не provider login, live Zvuk capture, Apple account write или полноту больших библиотек.

## Текущая проверка авто-подбора (2026-10-28)

Свежая браузерная сессия загрузила все 6 демо-записей, получила результаты Apple для 6/6 и завершилась без ошибок в консоли. Две записи были авто-выбраны как уникальные metadata matches на 98%; четыре остались на ручную проверку из-за неоднозначности. Это подтверждает работу UI-пути и осознанный review fallback на маленьком демонстрационном списке, но не измеряет точность на реальной библиотеке и не доказывает масштаб на тысячах.
