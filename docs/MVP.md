# Локальный прототип переноса между сервисами

Целевая функция — перенос лайков и плейлистов в любом направлении между Spotify, Apple Music, Яндекс Музыкой и Звуком. Сейчас локальное расширение читает Звук и содержит экспериментальные Spotify/Yandex read-only connectors. Apple используется пока только как каталог сопоставления; записей ещё нет.

## Что можно попробовать

1. Открыть Web Player Spotify или сайт Звука и войти штатным способом.
2. Выбрать источник и передать библиотеку из локального расширения; также доступны демо-данные и CSV/JSON.
3. Искать композиции в каталоге Apple. Сопоставитель автоматически выбирает только единственный результат с высокой уверенностью; неоднозначные результаты остаются на ручную проверку.
4. При необходимости поправить запрос или версию, исключить запись либо выбрать совпадение вручную.
5. Скачать JSON-план `music-transfer-plan` с source/target provider IDs, исходными ID/ISRC/метаданными, target track IDs, методом и оценкой совпадения, playlist-порядком, полнотой и пропусками.

## Данные и границы

- CSV и JSON читаются браузером и не отправляются на сервер проекта.
- Передача из Chrome connector доступна с локальных адресов `127.0.0.1:8000/8001` и `localhost:8000/8001`; service worker передаёт только полностью подтверждённый snapshot, без cookies и токенов.
- Поиск обращается напрямую из браузера к публичному Apple iTunes Search API. Apple получает введённые названия и исполнителей. Поддерживаются storefronts AE, US, GB, CA и AU.
- Первичный порог авто-подбора консервативный и пока не откалиброван на реальных библиотеках: exact ISRC принимается автоматически; по метаданным — только при уверенно высоком score и заметном отрыве от второго кандидата. Совпадение версий (live/remix/remaster и др.) проверяется отдельно. Массовый перенос тысяч записей ещё не подтверждён.
- Matcher, `demo/transfer-core.js` и `demo/transfer-engine.js` отделяют модель данных, план и orchestration от сервисов: общий поиск объединяет повторы и ограничивает конкуренцию, общий reader проходит cursor-страницы и сохраняет playlist positions. Модель допускает любой из четырёх сервисов как источник/назначение; реальный network adapter пока есть только для поиска по публичному Apple каталогу.
- Общий executor теперь задаёт целевой поток для будущих адаптеров: требует явного подтверждения и подтверждённой полноты снимка, читает существующую целевую коллекцию, пропускает уже сохранённые likes, пишет bounded batches, сохраняет checkpoints и сверяет результат через read-back. Для playlists сохраняет mapping, пустые коллекции и порядок. Ни один провайдерский account adapter пока не подключён.
- План может представлять один mixed-перенос всей библиотеки: likes идут отдельными `add_to_favorites`, playlist items — в соответствующие target playlists; executor читает и сверяет оба типа назначения независимо. Это пока preview/core слой, реальные сервисные записи не подключены.
- План описывает нативное действие `add_to_favorites` или `add_to_playlist`, но ни одна запись в сервис назначения не выполняется. В файле `mode` равен `preview-only`, а `execution.writesPerformed` — `0`.
- Spotify получил экспериментальный read-only connector из уже открытой вкладки. Он проверяет completeness лайков, каталога и плейлистов; live Spotify сессия пока не проверена. Подробности — в [`SPOTIFY_CONNECTOR.md`](SPOTIFY_CONNECTOR.md).
- Локальный Zvuk connector собирает лайки и плейлисты, сверяет totals и передаёт подтверждённый snapshot. Spotify и Яндекс readers экспериментальны и не live-verified; у Яндекса likes revision проверяется, но общий playlist catalog не имеет независимого total в изученном контракте. Ни один writer не подключён; Apple account adapter и end-to-end направления остаются незавершёнными.

## Запуск

Из корня проекта:

```bash
python3 -m http.server 8000 --bind 127.0.0.1 --directory demo
```

Открыть <http://127.0.0.1:8000>. Для сетевого поиска нужен локальный HTTP-сервер: при открытии `index.html` как `file://` браузер может заблокировать запрос к каталогу.

Для прямой передачи библиотеки из расширения откройте одну из поддержанных локальных страниц (`127.0.0.1:8000/8001` или `localhost:8000/8001`) и перезагрузите её после установки/обновления расширения. Сервер раздаёт файлы из текущего checkout. Если переключить checkout на ветку, где нет `demo/`, уже запущенный сервер продолжит слушать порт, но будет возвращать `404`. Для параллельной работы с исследовательской веткой используйте отдельный worktree для `feature/interactive-importer-mvp` и запускайте команду из него.

## Ручная проверка

В браузере проверены поиск для 6 демо-треков, формирование и скачивание provider-neutral JSON-плана: `type=music-transfer-plan`, source `zvuk`, target `apple-music`, три операции и три записи review/skip, `execution.writesPerformed=0`. Дополнительно загружен JSON fixture в формате Zvuk playlist export: оба трека распознаны, порядок/тип коллекции показаны, ошибок консоли нет. Локальный extension→app handoff добавлен, но ещё не проверен с установленным расширением. Это не подтверждает provider login, live Zvuk capture, Apple account write или полноту больших библиотек.

## Текущая проверка авто-подбора (2026-10-28)

Свежая браузерная сессия загрузила все 6 демо-записей, получила результаты Apple для 6/6 и завершилась без ошибок в консоли. Две записи были авто-выбраны как уникальные metadata matches на 98%; четыре остались на ручную проверку из-за неоднозначности. Это подтверждает работу UI-пути и осознанный review fallback на маленьком демонстрационном списке, но не измеряет точность на реальной библиотеке и не доказывает масштаб на тысячах.

Смешанный core сценарий отдельно прогнан через mock destination adapter: один `add_to_favorites`, один `add_to_playlist`, пустой плейлист сохранён, read-back завершился `complete`. Extension→app handoff проверяется отдельно после установки обновлённого unpacked extension.

## Статус охвата

Проект не поддерживает заявленный полный охват: ни одно из 16 направлений и ни один live target write пока не прошли end-to-end проверку. Общий core и два локальных source reader — только основа дальнейшей реализации.

Подробности Yandex reader и неопровергнутые runtime/CORS ограничения: [`YANDEX_CONNECTOR.md`](YANDEX_CONNECTOR.md).
