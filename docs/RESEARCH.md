# Исследование музыкального импорта

Дата первичного обзора: 27 октября 2026. Это рабочая техническая карта, не обещание неизменности API: у нескольких провайдеров эндпоинты и условия доступа меняются без обратной совместимости.

## Цель

Переносить сохранённые треки (лайки), а затем плейлисты и прочие элементы библиотеки из Звука, Spotify и Яндекс Музыки в Apple Music. Требования: без платных агрегаторов, без искусственного лимита на объём миграции, аккуратное сопоставление версий треков, понятный список несовпадений и безопасное обращение с учётными данными. Перенос аудиофайлов не требуется: API работают с каталогами и записями библиотек, а не дают право переносить потоковые аудиофайлы между сервисами.

## Краткий вывод

- Для Spotify есть официальный Web API с OAuth PKCE и доступом к сохранённым трекам. Но в действующем Development Mode Spotify указал ограничение до пяти пользователей на приложение и требование Premium для владельца приложения. Для личного инструмента это может подойти, если аккаунт соответствует условиям; для распространения — нет без другой категории доступа.
- Apple Music имеет официальный API: поиск каталога, чтение библиотеки и добавление записи в избранное доступны с пользовательским Music User Token. Добавление избранного документировано как `POST /v1/me/favorites`; для песни это должно появиться в плейлисте Favorite Songs. Создание токена разработчика и получение пользовательского разрешения — отдельные шаги. Надо отдельно проверить требования Apple Developer Program для выбранного способа выдачи токена до выбора финального UX.
- Для Яндекс Музыки есть зрелая, активно документируемая сообществом Python-библиотека и OAuth Device Flow, но API неофициальный. Библиотека умеет получать лайкнутые треки и ставить/снимать лайки.
- Для Звука найдены две неофициальные реализации. Переданный `ZvukDownloader` умеет читать профиль, треки/альбомы/плейлисты и получать ссылки на поток, но в просмотренном коде не найдено чтение или изменение пользовательских лайков. У него cookie `auth` копируется вручную из браузерной сессии. Библиотека `Aiving/sberzvuk-api` работает через GraphQL и `X-Auth-Token`, имеет анонимный токен и чтение каталога/плейлистов, но тоже не показывает операций с лайками.
- Открытые проекты пригодны как материал для изучения, но ни один из просмотренных не подтверждён как надёжное готовое решение для всех трёх источников → Apple Music без оговорок. Особенно внимательно нужно оценить то, что автоматизирует приватный API сайта или просит скопировать токен сессии.

## Матрица источников и назначений

| Сервис | Доступ к лайкам | Авторизация | Статус API | Что блокирует готовый бесплатный путь |
|---|---|---|---|---|
| Spotify | Официальное чтение сохранённых треков; запись через библиотечные эндпоинты | OAuth 2.0 Authorization Code + PKCE | Официальный, правила недавно менялись | Premium у владельца dev-приложения и лимит 5 пользователей в Development Mode; квоты/лимиты запросов |
| Apple Music | Официальный add-to-favorites; каталог и пользовательская библиотека | Developer Token + Music User Token / MusicKit permission | Официальный | Требования к Developer Token/ключам; пользователь должен разрешить доступ, подписка/доступность каталога влияют на добавление |
| Яндекс Музыка | Читать, добавлять и убирать лайки можно через неофициальную библиотеку | Device Flow (либо иные способы в документации библиотеки) | Неофициальный, reverse-engineered | API может измениться/закрыть OAuth Flow; сроки действия/обновления токена нужно реализовать самим |
| Звук | В просмотренных исходниках подтверждено чтение каталогов/плейлистов, лайки не подтверждены | `auth` cookie / `X-Auth-Token`; библиотека также берёт анонимный токен | Неофициальный, недокументированный провайдером | Нет публичного контракта и пока не найден подтверждённый лайк-эндпоинт; cookie — секрет браузерной сессии |

## Предлагаемая схема приложения

1. **Адаптер источника** авторизуется с минимальными разрешениями и отдаёт нормализованные элементы с исходными ID, названием, артистами, альбомом, длительностью, ISRC (если доступен), явностью/версией, датой и исходным порядком.
2. **Нормализованный экспорт** сохраняется локально как JSON/SQLite. Секреты и сами токены отделяются от каталога и не попадают в экспорт/логи.
3. **Сопоставление с каталогом Apple**: сначала ISRC, затем поиск по артисту/названию/альбому и длительности; учитываются версии (live/remaster/clean/explicit), региональный storefront и дубликаты. Неуверенные результаты оставляются для ручного выбора.
4. **Предпросмотр** показывает точные совпадения, спорные варианты, отсутствующие записи и потенциальные дубликаты до записи в библиотеку.
5. **Идемпотентная запись**: проверить, что песня не добавлена повторно; добавить лайки небольшими пачками; перепроверить результат и сохранить отчёт. Для API с лимитами использовать пагинацию, backoff на 429 и продолжение после сбоя.
6. **Восстановление**: исходный экспорт не изменяется. В отчёте остаются исходные ID и соответствия Apple, чтобы можно было повторить перенос или удалить только добавленные приложением элементы.

## Что означает «без ограничений» на практике

Нельзя гарантировать отсутствие ограничений со стороны сервисов. Реалистичная цель — не вводить собственный лимит количества треков: проходить пагинацию, батчировать запросы, продолжать с места сбоя и не терять непривязанные элементы. Но провайдеры могут ограничить приложение, доступ к отдельным аккаунтам, частоту запросов, регион каталога, членство/подписку и размер одного запроса. У Spotify в текущем Development Mode есть существенные лимиты доступа приложения. Бесплатность самостоятельного приложения также зависит от того, позволит ли Apple получить требуемые MusicKit credentials без платного членства для конкретного варианта развертывания.

## Проверить на практике следующим этапом

- Сначала посмотреть исходный код коннекторов и выписать фактические методы, параметры, scopes, пагинацию, обработку лимитов и лицензии.
- Для каждого сервиса сделать read-only прототип на тестовом/собственном аккаунте: экспорт лайков в обезличенный JSON, число элементов до/после пагинации, поля ID/ISRC/версия.
- Для Звука проверить в браузерных DevTools, какие запросы формируют экран «Мне нравится» и какие мутации вызываются при нажатии лайка. Не записывать значения cookie/token в репозиторий, скриншоты, логи или issue.
- Для Apple запросить минимальный доступ и проверить на нескольких тестовых песнях: поиск по ISRC, выдача storefront, добавление в Favorite Songs, повторный запрос, уже добавленная песня и недоступная песня.
- Зафиксировать лимиты Spotify/Apple с кодами ответов и актуальными квотами, а также выяснить стоимость/доступность developer credentials для личного локального сценария.
