# Матрица переноса между сервисами

Целевой сценарий — открыть штатные страницы музыкальных сервисов, войти в каждую свою учётную запись обычным способом, одним действием собрать доступные лайки и плейлисты и перенести их в выбранный сервис. Приложение не просит пароль, не требует OAuth-приложения владельца проекта и не загружает библиотеку на backend. В текущем MVP для чтения авторизованных страниц нужен локальный Chrome extension.

«Реализованы» означает, что есть отдельные source readers, каталоговый search и target writer с fixture coverage; это не доказывает, что конкретная пара прошла сквозной импорт в реальных аккаунтах. На текущий момент ни одна из 12 направленных пар не имеет live end-to-end evidence. В Chrome пользователя приложение также пока не получило `extension-ready`, поэтому реальные аккаунты не сканировались.

## Автоматический подбор для больших библиотек

- Сопоставитель использует ISRC, название, исполнителя, альбом, длительность и признаки версии записи. Поисковый запрос включает доступный альбом и автоматически расширяется, только если точный запрос ничего не нашёл. Точные ISRC совпадения выбираются автоматически; metadata-only выбор требует высокого score и отрыва от второго кандидата.
- Общий движок объединяет повторяющиеся запросы, ограничивает параллельность, повторяет временные ошибки и сохраняет прогресс. Apple объединяет до 25 ISRC в один запрос; Spotify и остальные каталоги пока ищутся по одному треку.
- Экран отображает не более 50 строк за раз. Это снижает UI-нагрузку, но не сокращает число отдельных API-поисков для Spotify, Яндекс Музыки и Звука.
- Пороги не откалиброваны на размеченных пользовательских библиотечных данных. В демо-выборке 4/6 совпадений выбраны автоматически после добавления альбома в запрос, но это слишком малая выборка для вывода о библиотеке или precision. Нельзя обещать, что для тысяч треков ручная проверка сведётся только к редким исключениям. До этого измеряются точность автоматических совпадений, ошибки по версиям и фактический rate limit каждого сервиса.

## Остаток до пригодного к повседневному использованию продукта

1. Подключить/обновить extension в Chrome, разрешить ему локальный origin и подтвердить handshake.
2. Снять read-only snapshots всех доступных аккаунтов и независимо подтвердить полноту каждой коллекции.
3. Прогнать все 12 route combinations на реальных тестовых библиотеках; сначала поиск и preview plan, затем маленькая запись с read-back.
4. Собрать labeled match decisions на разных языках, версиях, фичерингах и одинаковых названиях; настроить пороги на измеренную точность.
5. Измерить throughput и rate limits для нескольких тысяч tracks на каждом target. Добавлять batch API только там, где конкретный сервис действительно поддерживает групповой поиск.
6. Упростить распространение: сейчас требуется загрузить unpacked extension из исходников; установка через Chrome Web Store ещё не настроена. GitHub Pages deployment подготовлен, но требует включения в repo settings и release merge в `master`.
