# Каталог API-вызовов для миграции

Сводка маршрутов, которые нужны для чтения liked/saved tracks, поиска в каталоге и записи в Apple Music. Срез проверен 27.10.2026. Это не перечень всех методов Spotify, MusicKit, Яндекс Музыки или Звука. Для полного контекста, примеров ответов и исходников см. провайдерские заметки.

## Уровни подтверждения

- **Official** — опубликованный контракт провайдера.
- **Community** — маршрут и схема описаны сторонней библиотекой; провайдер не гарантирует совместимость.
- **Private web API** — внутренний web-player endpoint, наблюдён в браузере и воспроизведён чистым HTTP-клиентом; без стабильного публичного контракта.
- **Live read** означает, что выполнен только GET/read-only GraphQL; live write/mutation не выполнялся.

Ниже указываются только имена заголовков и шаблоны параметров. Access tokens, cookies, account IDs, реальные URI, cursors и записи пользовательской коллекции в этот файл не переносить.

## Clean terminal probes без авторизации (27.10.2026)

Публичный поиск и безопасный GraphQL `__typename` были проверены без cookies, bearer и аккаунтных данных. Отдельные GET-пробы synthetic playlist IDs 27.10.2026 использовали generic `MusicImporterResearch/1.0` User-Agent; user session и реальные playlist IDs не использовались.

## Apple Music

Apple также предлагает user-facing `Transfer Music` в Apple Music app/web. Это не опубликованный API route: пользователю нужна подписка Apple Music и вход в выбранный source account через интеграцию третьей стороны. Apple говорит, что поддерживаемые liked/loved songs идут в Favorite Songs; альтернативные совпадения доступны на review 30 дней, но сервисные плейлисты источника не переносятся. Список поддерживаемых providers зависит от аккаунта и не опубликован в статье, его надо проверить в UI. См. [инструкцию Apple Support AE](https://support.apple.com/en-ae/118249), опубликованную 31.03.2026.
