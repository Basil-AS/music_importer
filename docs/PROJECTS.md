# Готовые проекты и библиотеки

Срез GitHub и документации от 27.10.2026. Список — кандидаты для разбора, а не гарантия, что последний релиз у каждого работает или что заявленные возможности покрывают перенос лайков в Apple Music. Перед использованием проверить текущие коммиты, лицензии, открытые issues, способ авторизации и что делает код с токенами.

Доступен на iOS/iPadOS, Android и web | Нужна подписка Apple Music и Sync Library; поддерживаемые источники/объекты зависят от провайдера и региона. Сообщённая скорость около 1 трека/с; проверено автором на macOS Sonoma, на нашей машине не запускалось |

Для бесплатного локального режима изучать только `--level music`; не включать web/API уровни и их browser token flow. Сторонняя реализация, код/разрешения Music.app нужно проверить до использования |

Apple adapter пишет в Library/playlist, не Favorite Songs; использует Apple user token. Устаревшие зависимости/методы и ручная конфигурация; референс матчинг-пайплайна, не готовый мигратор |

Хороший backup/fallback без Web API quota | Архив нужно запросить и дождаться; это исходные метаданные, а не автоматическая запись в Apple. Для приложения нужен parser скачанного пользователем ZIP/JSON |
| [Yandex Music Transfer](https://github.com/yarikmsu/yandex-music-transfer) | MIT, проверенный HEAD `eb88366` (2026-10-20). Наиболее прямое готовое решение из просмотренных для Яндекс лайков → Apple Favorite Songs: CSV-export, Apple catalog match с ручным review, затем `POST /v1/me/favorites?ids[songs]=...`. Есть отдельные импортеры Spotify/YouTube/Amazon как targets. `import --apply` явно включает изменения. | Яндекс-вход — access token через неофициальный публичный Android client ID; Apple bearer + `media-user-token` вручную копируются из web-сессии, это не официальный third-party OAuth flow. Matching fuzzy по названию/артисту/длительности, без ISRC; ручная сверка в CSV нужна для live/remaster/обложек. Один Apple favorite запрос на трек, ~2 часа на 1,800 треков по README; Apple rate limit / подписка остаются. CSV экспорты содержат личные трековые ID/метаданные. Docker ограничивает контейнер и writable volume, но токены/выводы перед запуском нужно проверить. Мы код статически просмотрели, ничего не запускали и не писали в Apple. |
| [SongMirror](https://github.com/ahnafnafee/songmirror) | MIT, HEAD `76d3d27` (2026-10-21), self-hosted UI + CLI. Код Apple target читает системный Favorite Songs playlist и делает `POST /v1/me/favorites`; поддерживает Spotify, Apple, YouTube Music, Amazon, Deezer, TIDAL и Qobuz. Сильный ориентир для Spotify → Apple Favorites, N-way matching/sync и локального интерфейса. | Нет adapters для Яндекс Музыки или Звука. Spotify default auth — вставка `sp_dc` для внутреннего web-player API; Apple — вставка `authorization` bearer + `media-user-token` из web player. Это session-based, неподдерживаемые официальные контракты, хотя у Spotify есть OAuth fallback. Apple требует активную Music subscription для library operations; web bearer не равен Apple Developer token, сессия может истечь. Web UI без login, compose публикует `8888:8080`: README требует LAN-only; для практического запуска привязать порт к `127.0.0.1` и не выставлять наружу. Код реализует также удаление Apple Favorites, но публичная Apple справка гарантирует add; мы не проверяли удаление и не включаем его в план. Статический просмотр, без запуска и мутаций. |

Полезный reference к `/playlists/{id}/items` и `/me/library`, paging, checkpointing и защите от пустого/неполного экспорта. | Не переносит в Apple и не задаёт Apple Favorite Songs. Основной сценарий — два Spotify-аккаунта; код имеет fallback на старые endpoints. Экспорт включает данные библиотеки, локальные токены/JSON нужно беречь. Код статически просмотрен; тесты и live OAuth не запускались. |
| [Songport](https://github.com/xlollx/Songport) | Актуальный Android-переносчик; проверенная версия 1.1.0 (`5aba73a`, обновлён 27.10.2026), GPL-3.0. Spotify и Apple Music есть среди коннекторов; поддерживаются локальная обработка и собственный Spotify Client ID. | README перечисляет Liked Songs source/target для Spotify, Deezer и локальных серверов, но не для Apple Music. Spotify dev mode ограничен Premium-владельцем и числом пользователей; Apple-коннектор beta и REST-вариант связан с developer token. Не закрывает бесплатно перенос лайков в Apple Favorite Songs. |

Использует текущую web-сессию и частный `amp-api` response capture; playlists сканирует через UI. Требует вручную проверять скрипт и экспорт до запуска. |

## Что важно проверить в готовом коде

1. Вход через OAuth/системный браузер или запрос пароля/cookie/session token. Предпочтителен OAuth с явным consent; если надо использовать cookie, понимать риск и не отправлять его стороннему серверу.
2. Наличие `liked songs` в обоих направлениях и точный семантический смысл назначения: Apple Favorite Songs или отдельный playlist.
3. Пагинация и отсутствие внутреннего ограничения в 100/500/1000 элементов; обработка 429 и возобновление после обрыва.
4. ISRC, качество сопоставления, работа с explicit/live/remaster/compilation, ручной разбор неизвестных песен.
5. Проверка дубликатов и фактической записи на стороне Apple, а не только успешный HTTP статус.
6. Лицензия каждой библиотеки и совместимость с моделью локального приложения.

## Что можно взять в наш проект

- Переиспользовать типы и запросы в `ZvukDownloader`/`sberzvuk-api` как исследовательскую базу, но отделить чтение каталога от скачивания аудио.
- Для Звука начать с read-only `trudenboy/zvuk-music`: это первый найденный актуальный коннектор с методами лайков и MIT лицензией.
- Использовать `yandex-music-api` как эталон списка методов/моделей, начиная с read-only выгрузки лайков.
- Для Spotify сначала проверить Apple built-in transfer и при необходимости официальный Spotify data export; Web API оставить вариантом при выполнении условий Spotify.
- Для готового направления Яндекс → Apple Favorites протестировать `yarikmsu/yandex-music-transfer` после независимой проверки кода и только с dry-run/match: он уже делает нужный `POST /v1/me/favorites`, но использует web-session Apple tokens и неофициальный Yandex OAuth client.
- Для Spotify → Apple Favorites изучить Apple target/matcher `ahnafnafee/songmirror`; если повторять, заменить `sp_dc` на официальный OAuth где это возможно и не открывать loginless UI за пределы localhost. У проекта нет источников Яндекс/Звук.
- Использовать `Ruhrkrieger/spotify-account-migrator` как reference на актуальные после февраля 2026 Spotify endpoints; сам проект мигрирует только между Spotify аккаунтами.
- Для локального Mac проверить связку `YandexMusic_to_AppleMusic` Music.app import + AppleScript Favorite (`obitech` gist): она может дать бесплатную запись в настоящий Favorites без MusicKit REST API. Сначала проверить 2–3 тестовых трека, включая повторный запуск и неподдерживаемый каталоговый результат.
- Официальный MusicKit API требует developer token; кандидатные бесплатные скрипты обходятся токенами web-сессии Apple, но это личные сессионные секреты и неподдерживаемый web-player контракт. Не строить на нём внешнее облачное приложение.
- `YandexMusic_to_AppleMusic` и `mixxer` могут ускорить экспорт и catalogue matching, но их операции Apple Library не равны записи в Favorite Songs.
- Сначала реализовать небольшую собственную локальную миграцию с форматом промежуточного экспорта и ручным подтверждением несовпадений. Приватные API оставить изолированными адаптерами, чтобы замена одного провайдера не меняла ядро.
