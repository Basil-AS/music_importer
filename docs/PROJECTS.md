# Готовые проекты и библиотеки

Срез GitHub и документации от 27.10.2026. Список — кандидаты для разбора, а не гарантия, что последний релиз у каждого работает или что заявленные возможности покрывают перенос лайков в Apple Music. Перед использованием проверить текущие коммиты, лицензии, открытые issues, способ авторизации и что делает код с токенами.

Проверка исходников уточнила разницу двух Spotify-входов: официальный PKCE-провайдер вызывает `/me/tracks?limit=50` и требует пользовательский Client ID; встроенный Bridge читает через Spotify Web Player private API и сам показывает предупреждение о неподдерживаемом маршруте и условиях Spotify. Идеи локального UX и локального хранилища полезны, готовым бесплатным Favorite Songs importer этот проект не является.

Скрипт пишет title/artist в Script Editor log, что нужно убрать в приватной реализации. Запускался только статический разбор, не изменение музыкальной библиотеки.

## Что важно проверить в готовом коде

1. Вход через OAuth/системный браузер или запрос пароля/cookie/session token. Предпочтителен OAuth с явным consent; если надо использовать cookie, понимать риск и не отправлять его стороннему серверу.
2. Наличие `liked songs` в обоих направлениях и точный семантический смысл назначения: Apple Favorite Songs или отдельный playlist.
3. Пагинация и отсутствие внутреннего ограничения в 100/500/1000 элементов; обработка 429 и возобновление после обрыва.
4. ISRC, качество сопоставления, работа с explicit/live/remaster/compilation, ручной разбор неизвестных песен.
5. Проверка дубликатов и фактической записи на стороне Apple, а не только успешный HTTP статус.
6. Лицензия каждой библиотеки и совместимость с моделью локального приложения.

## Что можно взять в наш проект

- Переиспользовать типы и запросы в `ZvukDownloader`/`sberzvuk-api` как исследовательскую базу, но отделить чтение каталога от скачивания аудио.
- Для Звука начать с read-only `trudenboy/zvuk-music`: это первый найденный актуальный коннектор с методами лайков и MIT лицензией.
- Использовать `yandex-music-api` как эталон списка методов/моделей, начиная с read-only выгрузки лайков.
- Для Spotify без Developer Mode app/Premium сначала использовать официальный `YourLibrary.json` archive: локальный ZIP/JSON импорт не требует OAuth и не ограничен Spotify API quota. Для matcher/pipeline изучить `tapeit`, но он сейчас пишет Apple Library, не Favorite Songs, и его официальный Spotify auth всё ещё упирается в Premium.
- Использовать `liMusic` и `Namida` как независимые read-only references для типичной `YourLibrary.json` структуры; пользовательский архив в репозиторий не класть и не посылать на сервер.
- Для возможного одноразового no-code решения сначала проверять встроенный Apple Transfer: это единственный просмотренный вариант без дополнительной платы за мигратор, хотя нужна подписка Apple Music, поддержка источника зависит от аккаунта/региона, а live UI ранее вернул `Transfer Service is Busy`. Soundiiz не переносит избранные песни на бесплатном плане; TuneMyMusic заявляет Favorites, но ограничивает бесплатный план 500 треками.
- Для готового направления Яндекс → Apple Favorites протестировать `yarikmsu/yandex-music-transfer` после независимой проверки кода и только с dry-run/match: он уже делает нужный `POST /v1/me/favorites`, но использует web-session Apple tokens и неофициальный Yandex OAuth client.
- Для Spotify → Apple Favorites изучить Apple target/matcher и favorite-sync engine `ahnafnafee/songmirror`. Текущий HEAD уже умеет dry-run, синхронизацию нативных Favorites и ограниченный writeback; повторять этот путь можно только после отдельной оценки приватного Spotify/Apple session auth и правил провайдеров. Он не поддерживает Яндекс/Звук. Для локального пробного запуска сначала проверить контейнер/секреты и bind только на localhost: UI без login хранит tokens и библиотечные данные на диске.
- Новый одноимённый `m1r0lY/songmirror` также не даёт обещанный UX «войти и готово»: Spotify и Apple требуют ручной копии приватных session credentials, а Yandex/Zvuk adapters отсутствуют. Он полезен только как дополнительная проверка native favorites endpoints и dry-run/guard design; не запускать его web UI в LAN без auth.
- Для resumable экспорта, dry-run и отчётов совпадений сравнить `twttr/sp2ya`; он не является Apple-импортёром, но его checkpoint/cache/CSV подход полезен для дизайна нашего пайплайна.
- `iamaburu/yandex-to-spotify` показывает более свежий UX с ручным review и localhost UI, плюс реестр собственных записей для undo. Заимствовать идеи кэша и журнала можно; проверить новый Spotify OAuth/лимиты, не считать проект прямой опцией Apple.
- `MarshalX/yandex2spotify` полезен как пример Yandex liked tracks + playlist export и Spotify OAuth импорта. Не брать его Spotify OAuth tutorial как актуальную без перепроверки на действующей официальной документации 2026 года.
- Использовать `Ruhrkrieger/spotify-account-migrator` как reference на актуальные после февраля 2026 Spotify endpoints; сам проект мигрирует только между Spotify аккаунтами.
- Для локального Mac проверить связку `YandexMusic_to_AppleMusic` Music.app import + AppleScript Favorite (`obitech` gist): она может дать бесплатную запись в настоящий Favorites без MusicKit REST API. Сначала проверить 2–3 тестовых трека, включая повторный запуск и неподдерживаемый каталоговый результат.
- Официальный MusicKit API требует developer token; кандидатные бесплатные скрипты обходятся токенами web-сессии Apple, но это личные сессионные секреты и неподдерживаемый web-player контракт. Не строить на нём внешнее облачное приложение.
- `YandexMusic_to_AppleMusic` и `mixxer` могут ускорить экспорт и catalogue matching, но их операции Apple Library не равны записи в Favorite Songs.
- Сначала реализовать небольшую собственную локальную миграцию с форматом промежуточного экспорта и ручным подтверждением несовпадений. Приватные API оставить изолированными адаптерами, чтобы замена одного провайдера не меняла ядро.
