## SongMirror: что стоит перенять

Клонированный для чтения snapshot находится вне проекта в `/tmp/songmirror-review`. Смотрелись `engine/matching.py`, `engine/resolve_cache.py`, Spotify/Apple account connectors и transfer services; код не исполнялся и не копировался.

- Matching совмещает hard identifiers, RapidFuzz token scoring, Jaro-Winkler, transliteration и gates по performer/version/duration. Наш static matcher теперь добавляет кириллическую транслитерацию и удаляет `feat.` из title scoring без снижения автоматического порога.
- Resolve cache хранит пользовательские/автоматические mappings раздельно, наследует положительные результаты из родственных профилей и не наследует отрицательные ответы. Текущий IndexedDB cache хранит до 12 нормализованных кандидатов на успешный поиск или короткую отрицательную выдачу, ранжирует выдачу перед ограничением и сохраняет выбранный пользователем вариант; учитывает storefront и public-preview/account режим Apple Music; совпадения живут 30 дней, пустая выдача 7 дней. Ручные запросы и сетевые ошибки не сохраняются; Yandex album ID сохраняется для последующей записи плейлиста. Решения по match/исключению хранятся отдельно до 180 дней и восстанавливаются только если прежний target ID присутствует в новых кандидатах. Локальный job journal теперь сохраняет recovery plan и поддерживает карту созданных целевых плейлистов, удаляя эти данные после успеха или ручной сверки; writers используют локальные checkpoint и recovery plan; продолжение требует явного подтверждения и сверки уже записанного префикса.
- Transfer orchestration у SongMirror включает progress, per-provider safety caps и history. Наш браузерный app хранит recovery plan локально и может продолжить запись у всех четырёх целей, если target playlist ID сохранён: writer сверяет точный префикс и добавляет остаток. Если ID не успел сохраниться или порядок расходится, требуется ручная сверка. Критичные требования для тысяч треков остаются: bounded batches, provider rate-limit profiles и precision/recall метрики на реальных совпадениях; никакой live end-to-end transfer ещё не подтверждён.
- Spotify `sp_dc` и Apple Music token paste убирают developer app setup, но заставляют пользователя вручную вытаскивать секреты из DevTools. Наше расширение сохраняет более простой UX: команды отправляются в уже авторизованную вкладку, без чтения cookie database и копирования bearer tokens в приложение.

## Требования к интеграции проектов

Ни один найденный проект не закрывает одновременно Spotify, Apple Music, Яндекс Музыку и Звук для likes и playlists во всех направлениях с чистым пользовательским входом и локальным исполнением. `synchro` заявляет likes для всех четырёх, но README не заявляет playlists или простой GUI; Songport и SongMirror имеют более зрелый transfer UX, но не закрывают два российских сервиса или требуют ручного копирования credentials. Официальная миграция Звука полезна для части входящих playlists, но не переносит likes в «Любимое» и не экспортирует из Звука. Поэтому локальная extension-архитектура остаётся подходящей базой, а проекты используются как независимые API/matching/workflow references.

Прежде чем заимствовать код, фиксировать источник файла/алгоритма, лицензию репозитория и runtime dependency, затем сохранять upstream attribution. Для реализации сервиса нужны отдельные evidence по login, полной пагинации likes/playlists, поиску целевого каталога, записи и read-back; README или fixture сами по себе live-совместимость не подтверждают.

Нет Яндекса/Звука; Spotify требует собственный Client ID/Secret пользователя и OAuth, Apple Shortcut надо вручную создать в Shortcuts.app; для точных Apple catalog links нужны собственные MusicKit credentials (этот шаг необязателен для локального favorite setter). Name+artist resolver может fallback-нуться на title-only, а Shortcut берёт только первый store-search result; импорт требует review. UI запускается через `make dev` с `uv`/`npm`, это не готовый one-click installer. Статически просмотрены README, AppleScript, provider и web API; live account/write и upstream tests не запускались. |

## Что важно проверить в готовом коде

1. Вход через OAuth/системный браузер или запрос пароля/cookie/session token. Предпочтителен OAuth с явным consent; если надо использовать cookie, понимать риск и не отправлять его стороннему серверу.
2. Наличие `liked songs` в обоих направлениях и точный семантический смысл назначения: Apple Favorite Songs или отдельный playlist.
3. Пагинация и отсутствие внутреннего ограничения в 100/500/1000 элементов; обработка 429 и возобновление после обрыва.
4. ISRC, качество сопоставления, работа с explicit/live/remaster/compilation, ручной разбор неизвестных песен.
5. Проверка дубликатов и фактической записи на стороне Apple, а не только успешный HTTP статус.
6. Лицензия каждой библиотеки и совместимость с моделью локального приложения.

## Что можно взять в наш проект

- Переиспользовать типы и запросы в `ZvukDownloader`/`sberzvuk-api` как исследовательскую базу, но отделить чтение каталога от скачивания аудио.
- Для Звука начать с read-only `trudenboy/zvuk-music`: это первый найденный актуальный коннектор с методами лайков и MIT лицензией.
- Использовать `yandex-music-api` как эталон списка методов/моделей, начиная с read-only выгрузки лайков.
- Для Spotify без Developer Mode app/Premium сначала использовать официальный `YourLibrary.json` archive: локальный ZIP/JSON импорт не требует OAuth и не ограничен Spotify API quota. Для matcher/pipeline изучить `tapeit`, но он сейчас пишет Apple Library, не Favorite Songs, и его официальный Spotify auth всё ещё упирается в Premium.
- Использовать `liMusic` и `Namida` как независимые read-only references для типичной `YourLibrary.json` структуры; пользовательский архив в репозиторий не класть и не посылать на сервер.
- Для возможного одноразового no-code решения сначала проверять встроенный Apple Transfer: Apple документирует liked/loved → Favorite Songs, но прямо называет функцию сторонним transfer service и не публикует общей цены, квоты или списка sources. Не считать его заранее бесплатным/безлимитным; нужна подписка Apple Music и фактическая проверка доступности source в аккаунте. Live UI ранее вернул `Transfer Service is Busy`. Soundiiz Free не переносит favorites; TuneMyMusic заявляет Favorites, но ограничивает бесплатный план 500 треками.
- Для готового направления Яндекс → Apple Favorites протестировать `yarikmsu/yandex-music-transfer` после независимой проверки кода и только с dry-run/match: он уже делает нужный `POST /v1/me/favorites`, но использует web-session Apple tokens и неофициальный Yandex OAuth client.
- Для Spotify → Apple Favorites изучить Apple target/matcher и favorite-sync engine `ahnafnafee/songmirror`. Текущий HEAD уже умеет dry-run, синхронизацию нативных Favorites и ограниченный writeback; повторять этот путь можно только после отдельной оценки приватного Spotify/Apple session auth и правил провайдеров. Он не поддерживает Яндекс/Звук. Для локального пробного запуска сначала проверить контейнер/секреты и bind только на localhost: UI без login хранит tokens и библиотечные данные на диске.
- Новый одноимённый `m1r0lY/songmirror` также не даёт обещанный UX «войти и готово»: Spotify и Apple требуют ручной копии приватных session credentials, а Yandex/Zvuk adapters отсутствуют. Он полезен только как дополнительная проверка native favorites endpoints и dry-run/guard design; не запускать его web UI в LAN без auth.
- Для resumable экспорта, dry-run и отчётов совпадений сравнить `twttr/sp2ya`; он не является Apple-импортёром, но его checkpoint/cache/CSV подход полезен для дизайна нашего пайплайна.
- `iamaburu/yandex-to-spotify` показывает более свежий UX с ручным review и localhost UI, плюс реестр собственных записей для undo. Заимствовать идеи кэша и журнала можно; проверить новый Spotify OAuth/лимиты, не считать проект прямой опцией Apple.
- `MarshalX/yandex2spotify` полезен как пример Yandex liked tracks + playlist export и Spotify OAuth импорта. Не брать его Spotify OAuth tutorial как актуальную без перепроверки на действующей официальной документации 2026 года.
- Использовать `Ruhrkrieger/spotify-account-migrator` как reference на актуальные после февраля 2026 Spotify endpoints; сам проект мигрирует только между Spotify аккаунтами.
- Для локального Mac проверить связку `YandexMusic_to_AppleMusic` Music.app import + AppleScript Favorite (`obitech` gist): она может дать бесплатную запись в настоящий Favorites без MusicKit REST API. Сначала проверить 2–3 тестовых трека, включая повторный запуск и неподдерживаемый каталоговый результат.
- Официальный MusicKit API требует developer token; кандидатные бесплатные скрипты обходятся токенами web-сессии Apple, но это личные сессионные секреты и неподдерживаемый web-player контракт. Не строить на нём внешнее облачное приложение.
- `YandexMusic_to_AppleMusic` и `mixxer` могут ускорить экспорт и catalogue matching, но их операции Apple Library не равны записи в Favorite Songs.
- Сначала реализовать небольшую собственную локальную миграцию с форматом промежуточного экспорта и ручным подтверждением несовпадений. Приватные API оставить изолированными адаптерами, чтобы замена одного провайдера не меняла ядро.
