# Кэш библиотек и следующие улучшения интерфейса

## Уже работает

- На узких экранах индикатор этапов оставляет подпись у текущего шага и сохраняет остальные подписи для скринридера; названия сервисов и кнопки в карточках не опускаются ниже 12–13 px.
- Полные подтверждённые снимки хранятся локально в `chrome.storage.local`; данные не отправляются на backend проекта.
- При старте приложение сначала показывает сохранённые снимки. У карточек отображается возраст последнего полного чтения.
- Автоматическое полное перечитывание начинается, если снимка нет, он не подтверждён или ему больше шести часов. Кнопка «Обновить библиотеки» запускает полный сбор сразу; отдельная кнопка в карточке позволяет повторить только этот сервис.
- Ход сбора виден отдельно в карточке каждого сервиса с собственным индикатором и сообщением; когда сервис сообщает числовой прогресс, полоска показывает загруженное количество и общий объём. Сбор одного сервиса можно повторить, не ожидая остальные; общий статус показывает краткую сводку.
- Во время обновления остаётся доступен прошлый полный снимок. Ошибка чтения не заменяет его неполными данными и не продлевает возраст.
- `demo/library-cache.js` реализует freshness labels и безопасные примитивы pulse/merge для будущего использования. Pulse считается доказательством неизменности только при полном каталоге и стабильной revision/fingerprint; одного количества элементов недостаточно. Удаление коллекции разрешено только после полного каталожного ответа.
- Результаты поиска и решения по совпадениям можно очистить отдельно от снимков библиотек.

## Что пока не подключено

- У сервисов пока нет единого подтверждённого дешёвого pulse-контракта. Поэтому приложение не обещает фоновую инкрементальную проверку за 10 минут и делает полный сбор не чаще одного раза в шесть часов автоматически.
- Pulse-проверки и перечитывание только изменившихся плейлистов не подключены к provider adapters. Их можно добавлять отдельно для сервиса, когда проверены полнота каталога, стабильная revision/fingerprint и обработка удаления.
- Размер списка, длительность сканирования и сервисные лимиты на больших реальных библиотеках пока не измерены.

## Дальнейший UX backlog

- На карточках сервисов отдельно показываются лайки, подтверждённые альбомы, плейлисты, статус входа и возраст снимка. В панели приватности доступны очистка снимков и оценка их локального размера.
- Review уже поддерживает фильтры по статусу, сортировку по названию/исполнителю/уверенности и групповое включение совпадений на странице. Дальше остаются раскрытие нескольких кандидатов без перегруза и полная клавиатурная навигация.
- Для больших коллекций виртуализировать строки; после UI pass повторно проверить контраст, фокус и обе темы на визуальном Chrome-сеансе.
- Отображать этапы записи, ожидание `Retry-After`, отмену и точный отчёт, сохраняя возможность безопасно сверить незавершённый перенос.

Каждый пункт backlog нужно закрывать отдельным коммитом с fixture-проверками. Живая проверка записи требует одноразовой тестовой коллекции и отдельного разрешения для конкретного маршрута.
