# Apple Music API: полный индекс официальных REST endpoints

Срез на 27.10.2026. Получено из официальной Apple Developer DocC JSON-документации: root API index → API category pages → symbols с `symbolKind=httpRequest`. В этом обходе найдено **138** документированных endpoint-операций и **119** уникальных method/path пар. Это каталог официальной REST API, не приватный Apple Music web-player API. Apple может обновлять документацию; при изменениях повторно собирать inventory из [официального API reference](https://developer.apple.com/documentation/applemusicapi).

## Авторизация

- Каждый REST запрос отправляется к `https://api.music.apple.com/v1` с `Authorization: Bearer <developer-token>`.
- Пути `/me/...` обслуживают персональные данные и требуют Music User Token в `Music-User-Token`; пользователь авторизуется через MusicKit. Пути `/catalog/{storefront}/...` работают с каталогом storefront и требуют developer token.
- Сводка токенов Apple: [Generating Developer Tokens](https://developer.apple.com/documentation/applemusicapi/generating-developer-tokens), [User Authentication for MusicKit](https://developer.apple.com/documentation/applemusicapi/user-authentication-for-musickit), [Handling Requests and Responses](https://developer.apple.com/documentation/applemusicapi/handling-requests-and-responses).

## Как читать

`{name}` — path parameter; query параметры отдельно перечислены без значений. HTTP status codes взяты из endpoint DocC page. Поля помечены `(required)` если Apple указывает их обязательными. Для миграции важны прежде всего catalog search/ISRC, multi-song fetch, user library reads и `POST /v1/me/favorites`.

В отличие от mutations, которые передают `ids` как query parameters, эти endpoints используют JSON request body. Body resource types связывают payload с официальной моделью Apple.

| Метод и путь | Операция | JSON body | Смысл body по Apple |
|---|---|---|---|
| `POST /v1/me/library/playlist-folders` | [Create a New Library Playlist Folder](https://developer.apple.com/documentation/applemusicapi/create-a-new-library-playlist-folder) | `LibraryPlaylistFolderCreationRequest` | The `POST` request containing the `name` and `parent` playlist folder for the playlist folder to be added. |
| `POST /v1/me/library/playlists` | [Create a New Library Playlist](https://developer.apple.com/documentation/applemusicapi/create-a-new-library-playlist) | `LibraryPlaylistCreationRequest` | The `POST` request containing the `name` `tracks` and `parent` playlist folder for the playlist to be added. |
| `POST /v1/me/library/playlists/{id}/tracks` | [Add Tracks to a Library Playlist](https://developer.apple.com/documentation/applemusicapi/add-tracks-to-a-library-playlist) | `LibraryPlaylistTracksRequest` | The `POST` request containing the `identifier` and `type` for the tracks to be added. |

## Важное различие для Favorites

Apple ratings (`/v1/me/ratings/...`) и Favorites (`/v1/me/favorites`) — разные операции. Rating write нельзя считать добавлением песни в системный Favorite Songs playlist. Для целевого переноса используем только documented `POST /v1/me/favorites`; точный live write/read-back остаётся отдельной будущей проверкой.

## Переносу лайков нужны в первую очередь

| Действие | Операция | Назначение |
|---|---|---|
| Подобрать песню по точному идентификатору | [Get Multiple Catalog Songs by ISRC](https://developer.apple.com/documentation/applemusicapi/get-multiple-catalog-songs-by-isrc) | `GET /v1/catalog/{storefront}/songs?filter[isrc]=...`; Apple указывает максимум 25 ISRC в одном запросе. |
| Добрать песни по ID | [Get Multiple Catalog Songs by ID](https://developer.apple.com/documentation/applemusicapi/get-multiple-catalog-songs-by-id) | Catalog lookup для уже известных Apple IDs. |
| Проверить personal library | [Get All Library Songs](https://developer.apple.com/documentation/applemusicapi/get-all-library-songs) / [Search for Library Resources](https://developer.apple.com/documentation/applemusicapi/search-for-library-resources) | Не добавлять повторно то, что уже находится в библиотеке; отдельный Favorite status можно сверить через personal ratings/collection read path, если он доступен. |
| Добавить в Favorite Songs | [Add resource to favorites](https://developer.apple.com/documentation/applemusicapi/add-resource-to-favorites) | `POST /v1/me/favorites?ids[songs]=...`; Apple документирует `202 Accepted`. Для песен это добавляет ресурс в playlist `Favorite Songs`; неподдержанные/не найденные IDs могут быть проигнорированы. |
| Альтернатива — обычная Library | [Add a Resource to a Library](https://developer.apple.com/documentation/applemusicapi/add-a-resource-to-a-library) | `POST /v1/me/library?ids[songs]=...`; это добавление в iCloud Music Library, не Favorite Songs. |

Для Apple Favorites в этом проекте не было выполнено live write. Документированные `202 Accepted` ответы означают принятие запроса, не синхронное завершение; после записи требуется read-back.
